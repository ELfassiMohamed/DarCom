 TASK 01 — Domain Entities (JPA)
--------------------------------------------------------------------------------
 Goal: Create the JPA domain model from API-Specification.md §3/§12/§13 as
       Hibernate-managed entities that generate the DDL via drop-and-create.

 Deliverable: 12 files — 7 entities + 5 enums. No repositories/services.

 Files created (src/main/java/com/backend/domain):
  1. domain/User.java                    @Table(users)
  2. domain/Listing.java                 @Table(listings)
  3. domain/Photo.java                   @Table(photos)
  4. domain/Booking.java                 @Table(bookings)
  5. domain/Message.java                 @Table(messages)
  6. domain/Report.java                  @Table(reports)
  7. domain/RefreshToken.java            @Table(refresh_tokens)
  8. domain/enums/UserRole.java          HOST, VISITOR, ADMIN
  9. domain/enums/ListingStatus.java     ACTIVE, HIDDEN, REMOVED
 10. domain/enums/BookingStatus.java     PENDING, CONFIRMED, REJECTED, CANCELLED + state machine
 11. domain/enums/ReportReason.java      SCAM, MISLEADING_LISTING, INAPPROPRIATE_BEHAVIOR, OTHER
 12. domain/enums/ReportStatus.java      OPEN, REVIEWED, DISMISSED, ACTIONED

 Global conventions (all 7 entities):
  - No inheritance/@MappedSuperclass (audit columns differ per table)
  - @Id @GeneratedValue(GENERATION.UUID) java.util.UUID, explicit @Column(name) snake_case
  - All @ManyToOne FetchType.LAZY, optional=false where FK NOT NULL
  - Only bidirectional: Listing.photos <-> Photo.listing (cascade ALL + orphanRemoval + @OrderBy sortOrder)
  - No Lombok, hand-written getters/setters, public no-arg ctor required by JPA
  - equals/hashCode: final, id-based (id!=null && id.equals(other.getId())), hash = Class.hashCode() (proxy-safe)
  - toString: scalar fields only (never association/collection, never passwordHash/tokenHash)
  - Timestamps: Instant (TIMESTAMPTZ) via @PrePersist/@PreUpdate, LocalDate for checkIn/checkOut
  - Enums: @Enumerated(STRING), never ORDINAL; Jakarta imports only

 Entity details:
  User: email(@Email @NotBlank unique 255), passwordHash(255), fullName(255), phone(30), role(UserRole 20),
        verified/blocked boolean, createdAt (TIMESTAMPTZ). No collections on User by design.
  Listing: host(User FK host_id), title(255), description(TEXT), city(120), address(255),
           pricePerNight(BigDecimal 10,2 @PositiveOrZero), currency(3 default MAD), mealsIncluded bool,
           activities @ElementCollection Set<String> -> listing_activities(listing_id, activity 120) LinkedHashSet,
           status(ListingStatus ACTIVE), photos List<Photo>, createdAt, updatedAt. Helpers addPhoto/removePhoto + clear-and-addAll setters.
  Photo: listing(FK listing_id), url(500 @NotBlank), sortOrder int 0. No timestamps.
  Booking: listing(FK), visitor(FK visitor_id), checkIn/checkOut LocalDate @NotNull, guestsCount int @Positive,
           status(BookingStatus PENDING), createdAt, updatedAt. No totalPrice/message fields. TODO checkOut>checkIn in service.
  Message: listing(FK), sender(FK sender_id), receiver(FK receiver_id), body(TEXT @NotBlank), sentAt(PrePersist), readAt.
           Threads derived via (listing_id, sender_id, receiver_id).
  Report: reporter(FK), reportedHost(FK reported_host_id), listing(FK nullable), reason(ReportReason 30),
          details(TEXT), status(ReportStatus OPEN), adminNotes(TEXT), createdAt, reviewedAt(admin action).
  RefreshToken: user(FK user_id), tokenHash(512 unique @NotBlank, stores hash never raw), expiresAt, createdAt,
                isExpired() = expiresAt < now, toString excludes hash.

 Companion changes:
  pom.xml: added jakarta.validation-api 3.0.2 (runtime, because jakarta.jakartaee-api is provided; same fix as persistence-api)
  persistence.xml (META-INF): added 7 explicit <class> entries for reliable discovery under RESOURCE_LOCAL/WAR (invest-pu retained)
  Drop-and-create retained: Hibernate rebuilds schema from annotations on each EMF start; data does not survive restart.

 Verification: mvn clean compile BUILD SUCCESS (13 src files with TestServlet), no FetchType.EAGER, no javax., no ORDINAL.

 1) persistence.JpaUtil  [src/main/java/com/backend/persistence/JpaUtil.java]
    Purpose: Single owner of EntityManagerFactory for whole app. Replaces inline
             Persistence.createEntityManagerFactory(...) from smoke checks.
             Uses Dotenv to inject DB_URL/DB_USER/DB_PASSWORD + driver.

    - private static final String PERSISTENCE_UNIT_NAME = "invest-pu"
      Constant matching persistence.xml persistence-unit name. Update in one place if renamed.

    - private static final EntityManagerFactory EMF = buildEntityManagerFactory()
      Eagerly built singleton, reused for all EntityManagers.

    - private JpaUtil() {}
      Prevent instantiation (utility class, final).

    - private static EntityManagerFactory buildEntityManagerFactory() : EntityManagerFactory
      Loads Dotenv.load(), builds Map<String,String> props:
        jakarta.persistence.jdbc.url      -> dotenv.get("DB_URL")
        jakarta.persistence.jdbc.user     -> dotenv.get("DB_USER")
        jakarta.persistence.jdbc.password -> dotenv.get("DB_PASSWORD")
        jakarta.persistence.jdbc.driver   -> "org.postgresql.Driver"
      Returns: Persistence.createEntityManagerFactory(PERSISTENCE_UNIT_NAME, props)

    - public static EntityManager createEntityManager() : EntityManager
      Delegates to EMF.createEntityManager(). Caller (currently manual, later Service) opens/closes transaction.

    - public static void shutdown() : void
      Closes EMF if open. Not yet wired; intended for ServletContextListener.contextDestroyed().

 2) repository.Pageable  [src/main/java/com/backend/repository/Pageable.java]
    Purpose: Typed pagination envelope. Every paginated repo method takes one
             Pageable instead of two raw ints. Validation here, size clamping (max 100) in Service/Resource.

    - public record Pageable(int page, int size)
      Compact record. Canonical constructor validates:
        if page < 0 throw IllegalArgumentException("page must be >= 0")
        if size < 1 throw IllegalArgumentException("size must be >= 1")

    - public int offset() : int
      Returns page * size (firstResult for JPA). Used by all paginated queries.

 3) repository.GenericRepository<T>  [src/main/java/com/backend/repository/GenericRepository.java]
    Purpose: Shared CRUD for all entities. UUID is hard-coded as ID type because
             Task 01 mandates UUID for every entity; no generic <ID> needed.

    Fields:
      protected final EntityManager em
      protected final Class<T> entityClass

    - public GenericRepository(EntityManager em, Class<T> entityClass)
      Constructor — borrows EM (never creates/closes), stores target class.

    - public Optional<T> findById(UUID id) : Optional<T>
      em.find(entityClass, id) wrapped in Optional.ofNullable. Proxy-safe.

    - public List<T> findAll(Pageable pageable) : List<T>
      Criteria API: cb.createQuery(entityClass), cq.select(cq.from(entityClass)), setFirstResult(offset)/maxResults(size).

    - public T create(T entity) : T
      em.persist(entity); return entity. Requires active transaction outside repo.

    - public T update(T entity) : T
      return em.merge(entity). Works for detached instances.

    - public void delete(T entity) : void
      em.remove(em.contains(entity) ? entity : em.merge(entity)) — merges first if detached to avoid IllegalArgumentException.

    - public void deleteById(UUID id) : void
      findById(id).ifPresent(this::delete) — no exception if missing.

    - public long count() : long
      Criteria: select(cb.count(cq.from(entityClass))), getSingleResult().

 4) repository.UserRepository extends GenericRepository<User>
    Serves: POST /auth/register (duplicate), POST /auth/login, POST /auth/resend-verification, GET /admin/users
    Constructor: public UserRepository(EntityManager em) -> super(em, User.class)

    - public Optional<User> findByEmail(String email) : Optional<User>
      JPQL: "SELECT u FROM User u WHERE u.email = :email" -> getResultStream().findFirst() (no NoResultException, returns empty Optional).
      Used for login lookup.

    - public boolean existsByEmail(String email) : boolean
      JPQL COUNT: "SELECT COUNT(u) FROM User u WHERE u.email = :email" -> count>0. Lightweight 409 check for register without hydrating User.

    - public List<User> search(UserRole role, Boolean verified, Boolean blocked, String searchText, Pageable pageable) : List<User>
      Criteria API with 4 optional filters. Builds Predicate[] via searchPredicates(...), where(cb), orderBy(createdAt DESC), paginated.
      Endpoint: GET /admin/users?role=&verified=&blocked=&search= (search matches fullName OR email, case-insensitive LIKE %text%).

    - public long countSearch(UserRole role, Boolean verified, Boolean blocked, String searchText) : long
      Same predicates as search() but select(cb.count(root)). For paginated envelope totalItems.

    - private Predicate[] searchPredicates(CriteriaBuilder cb, Root<User> root, UserRole role, Boolean verified, Boolean blocked, String searchText) : Predicate[]
      Adds: role==, verified==, blocked== if non-null; if searchText non-blank -> OR( lower(fullName) LIKE %lower%, lower(email) LIKE % ). Returns toArray.

 7) repository.BookingRepository extends GenericRepository<Booking>
    Serves: GET /bookings/mine, GET /bookings/received, overlap check for PATCH /bookings/{id}/status, delete guard DELETE /listings/{id}
    Constructor: public BookingRepository(EntityManager em)

    - public List<Booking> findByVisitor(User visitor, Pageable pageable) : List<Booking>
      JPQL: "SELECT b FROM Booking b WHERE b.visitor = :visitor ORDER BY b.createdAt DESC" paginated. For GET /bookings/mine.

    - public List<Booking> findByListingHost(User host, BookingStatus status, Pageable pageable) : List<Booking>
      JPQL with optional status: "SELECT b FROM Booking b WHERE b.listing.host = :host" + (status!=null ? " AND b.status = :status" : "") + " ORDER BY b.createdAt DESC"
      Uses TypedQuery, conditionally setParameter("status"). For GET /bookings/received?status= (across all host listings).

    - public List<Booking> findOverlapping(Listing listing, LocalDate checkIn, LocalDate checkOut, List<BookingStatus> statuses, UUID excludeBookingId) : List<Booking>
      JPQL: "SELECT b FROM Booking b WHERE b.listing = :listing AND b.status IN :statuses AND b.id <> :excludeId AND b.checkIn < :checkOut AND b.checkOut > :checkIn"
      Half-open interval overlap logic: [a1,a2) overlaps [b1,b2) iff a1<b2 && a2>b1. Same-day turnover (checkout==checkin) is NOT overlap. Backs PATCH /bookings/{id}/status auto-reject: on CONFIRMED, find other PENDING overlapping bookings to reject. Service decides when to call.

    - public boolean existsActiveBookingForListing(Listing listing) : boolean
      JPQL COUNT: "SELECT COUNT(b) FROM Booking b WHERE b.listing = :listing AND b.status IN :statuses" with PENDING,CONFIRMED -> count>0. Guard for DELETE /listings/{id} -> 409 CANNOT_DELETE_WITH_ACTIVE_BOOKINGS.

 8) repository.MessageRepository extends GenericRepository<Message>

      Returns chronological thread between two participants on one listing, regardless of direction. Resolving who userA/userB are (caller vs withUser) is Resource/Service, not repo.

    (Full detail in the root Task.txt — this file is the condensed mirror.)

    PURPOSE: Task 01 built the nouns (entities), Task 02 built the verbs that read
      and write them (repositories). Task 03 builds the rules — the layer that
      decides whether an operation is allowed and owns the transaction it runs in.
      Without it, 01+02 are a database access library with no business logic.

    LAYERING (spec §1: Resource -> Service -> Repository):
      api/       NOT BUILT (Task 04+)  HTTP, DTOs, auth, @Valid, exception mappers
      service/   THIS TASK            business rules + transaction boundary
      repository/TASK 02              query construction only, no rules
      domain/    TASK 01              shape + mapping + invariants
      persistence/ TASK 02            who owns the EntityManagerFactory

    FROM TASK 01: the entities Task 03 operates on (no domain/** edits — rules
      live in the service, not the model); the LAZY association shape, which is
      *why* a transaction boundary and a fetch strategy are needed at all; the
      proxy-safe id-based equals/hashCode that makes delete()'s ownership check
      safe on a proxy; setActivities()' clear-then-addAll, which is why update
      needs no explicit initialize but getById does; hibernate-core, so
      Hibernate.initialize() costs no new dependency.

    FROM TASK 02: JpaUtil, whose createEntityManager() TransactionRunner is the
      only caller of; the borrow-not-own repository contract (repos never create
      or close an EM), which is exactly what makes TransactionRunner possible;
      ListingRepository, which already covers most of what ListingService needs;
      Pageable, passed through unchanged. Task 02 shipped with "no transaction
      management (Service layer concern)" — that concern is what Task 03 delivers,
      so the two hand off cleanly rather than overlap.
    Task 02 gaps closed here: findByHost had no countByHost; no repo method
      fetched a Listing's associations. Both additive, no method re-signed.

    ADDS BACK: TransactionRunner (one place in the codebase allowed to call
      getTransaction(), reused by every future service), the ApiException tree
      (status + errorCode + message = the §1 envelope, so a future ExceptionMapper
      is pure passthrough), PagedResult<T> (shared, generic), and ListingService
      (the project's first real business rules).

    THE PROBLEM THIS TASK HAD TO SOLVE FIRST: no Auth layer exists, so nothing
      can hand a service a "who is calling". Resolved by having every such method
      take an already-resolved User (§3.1) — create(User, Listing) is fully
      callable today; resolving that User from a JWT is Task 04+ work. A fake
      auth context here would have been a layer built to be thrown away.

    STOPPED AT THE SERVICE LAYER: no DTOs, JAX-RS, exception mapper, CDI, JWT
      parsing, ValidationException/400, non-Listing services, photo endpoints, or
      tests. Each is either blocked on a missing prerequisite or is a Resource
      concern; building them now would mean building them twice.
